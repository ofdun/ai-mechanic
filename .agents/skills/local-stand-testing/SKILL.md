name: local-stand-testing
description: Поднимает и проверяет локальный ai-mechanic через Docker Compose с полным комплектом заказчика, сверяет профиль агента со стендом и прогоняет приёмку через Go, Python и браузер.
---

Работай из корня проверяемой ветки. Команды, профили и ожидаемые результаты собраны в [README локального стенда](../../../docs/local-stand/README.md).

1. Установи версию кода, режим агента и цель проверки. Для сравнения со стендом сверяй публичные параметры по списку в README. Доступ по SSH нужен только для фактической сверки удалённой конфигурации.
2. Найди пути из переданного пользователем контекста или локальных FLEET_DIR и MOCK_DIR. Проверь комплект через scripts/check_inputs.py. Если есть исходный ZIP, распакуй его в частный локальный каталог. При отсутствии или несовпадении файлов запроси конкретное имя, редакцию или путь к папке. Комплект Яндекс Диска, его производные, учётные данные и локальный .env остаются за пределами Git.
3. Подними Compose в отдельном локальном проекте и томе. Для паритета с профилем A проверь наличие локально заданного ключа и разрешение на передачу вопроса и выдержек руководства провайдеру. Предложи владельцу заполнить .env у себя, если ключ отсутствует. Пока ждёшь, выполни независимые проверки baseline и обозначь выбранный режим в результате.
4. Проверь запущенный стек через /health, /api/vehicles и UI. Для регрессии запусти customer_smoke.py с собственным временным состоянием. Подтверждение тестовой заявки проводи в локальном Mock ТОиР. Для голосового ввода различай тест с виртуальным микрофоном и реальную диктовку.
5. В результате укажи ревизию, профиль, число ТС и замеров, фактически пройденные сценарии и что потребовало бы ключа, живого Docker или физического телефона. Публикуй только разрешённые результаты проверок.
