---
name: local-stand-testing
description: Поднимает для текущей feature-ветки автономный Compose-стенд ai-mechanic с собственной БД, HTTPS, моками заказчика и браузером и прогоняет E2E через работающий стек.
---

Запускай команды из рабочей копии фичи. Вызови `python3 <путь-к-этому-скиллу>/scripts/stand.py`; путь к скиллу может вести в соседний checkout. Проект определяется по git-корню текущего каталога. В [README](../../../docs/local-stand/README.md) — структура комплекта, ручные проверки и параметры профилей.

1. Определи пути к оригинальным PDF и ZIP (`FLEET_DIR`) и распакованным штатным мокам (`MOCK_DIR`) из контекста или приватного .env. Если есть ZIP, распакуй локально. Если чего-то не хватает, запроси конкретный путь или файл. Исходники Яндекс Диска, ключи, индексы и БД остаются вне Git.
2. Запусти `stand.py up` для профиля A при доступном локальном ключе и согласованной передаче данных модели. При запросе полностью автономного, бесплатного или baseline-прогона используй `stand.py up --baseline`. Для запроса точного профиля A при отсутствии ключа попроси владельца заполнить локальный .env; укажи отдельно результат доступного baseline. Команда сама проверит комплект и построит весь стек, включая БД, поиск, речь и шлюз.
3. Выполни `stand.py e2e` на этом экземпляре. Для отдельного браузерного теста фичи используй `stand.py e2e --test <путь относительно tests/>`. Проверь пользовательский сценарий фичи поверх базового smoke. Детерминированный customer_smoke на временных сервисах не подтверждает работоспособность поднятого стека.
4. Для параллельных веток работай в отдельных git worktree. Для второго экземпляра в том же checkout передавай одинаковый `--instance ИМЯ` командам up/e2e/status/logs/down. Не переключай ветку в занятой рабочей копии. Для диагностики используй status и logs конкретного экземпляра.
5. Верни локальный HTTPS-адрес, путь к файлу доступа, профиль и результаты E2E. Оставь запрошенный стенд работающим для ручной проверки. По просьбе остановить вызови down выбранного экземпляра. Если Docker недоступен, явно укажи, какие проверки фактически выполнены.
