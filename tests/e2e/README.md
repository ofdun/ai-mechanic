# Мобильная приёмка веб-приложения

### Комплект заказчика

Перед запуском установите зависимости проекта, Playwright и Chromium, соберите фронтенд командами из следующего раздела. Укажите в `DATA_DIR` папку с шестью PDF, в `MOCK_DIR` — распакованный каталог со штатными заглушками. Запускайте из корня репозитория.

```bash
(cd app/backend && go build -tags=nomsgpack -o /tmp/mechanic-web .)
PYTHONPATH=. .venv/bin/python tests/e2e/customer_smoke.py --backend /tmp/mechanic-web \
  --data-dir "$DATA_DIR" --mock-dir "$MOCK_DIR"
```

Тест собирает командный индекс поиска и SQLite для читалки во временном каталоге. Для повторного запуска с готовой парой передайте `--index "$ARTIFACTS_DIR/manuals.sqlite3"`: каталог `retrieval/` должен лежать рядом.

Мобильный Chromium обращается к Go API. Тест отслеживает вызов реального `RetrievalEngine.search` на вопросе о термостате, проверяет модель двигателя в результатах и открывает найденную страницу. Для F08 он проверяет страницу 52 из черновика и подтверждает заявку в отдельном экземпляре Mock ТОиР. Проверяются также норматив на странице 137 для ЗМЗ-5234.10, повтор подтверждения, сбой записи, ошибочное распознавание и низкая уверенность.

Для проверки помех повторите команду с `--signal-warning`. Тест меняет качество одной записи в памяти своего Mock ML после создания черновика. Он проверяет отказ сервера при устаревшем черновике, отдельное согласие механика, порог в переведённом отчёте и квитанцию ТОиР.

### Учебная проверка без комплекта

Запускайте из корня checkout на Python 3.10+ и Node.js 18.x, 20.x или 22+. Для первого запуска нужен доступ к реестрам пакетов и загрузке браузера.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[api]' 'playwright>=1.50,<2'
.venv/bin/python -m playwright install chromium
npm --prefix app/frontend ci
npm --prefix app/frontend run build
PYTHONPATH=. .venv/bin/python tests/e2e/mobile_smoke.py
```

Если установлен Google Chrome, можно пропустить загрузку Chromium и передать тесту `--channel chrome`. На Linux системные библиотеки браузера можно установить командой `.venv/bin/python -m playwright install --with-deps chromium`.

Сценарий создаёт временный каталог, поднимает HTTP-сервисы на свободных loopback-портах и открывает собранное приложение с сенсорным вводом и экраном 390 × 844. Используются учебный справочник, PDF «Учебная инструкция стенда Д-01» и локальный планировщик. Для этого прогона достаточно файлов репозитория.

| Сценарий | Что проверяет браузер |
|---|---|
| C1, отклонение | Механик видит риск и работу. Встроенный просмотр открывает страницу 2. Проверяются оригинал, текст, переход на соседнюю страницу и возврат к прежней позиции отчёта. Черновик содержит работу, сессию и источник. Явное подтверждение возвращает номер заявки. Серверный повтор того же запроса с cookie механика возвращает прежний номер, в учебный ТОиР ушёл один POST. |
| F4, уточнение «Почему это опасно?» | Для Д-01 чат показывает риск предыдущей диагностики со ссылкой на страницу 2. После смены двигателя на Д-02 тот же вопрос получает ограничение. |
| C2, вопрос о перегоне | Введённый на телефоне вопрос получает ответ об отсутствии оснований для рекомендации. |
| Норма | После выбора другого ТС исчезают старая квитанция и работа. Новая проверка показывает норму и рекомендацию продолжить эксплуатацию. |
| C3, плохая запись | При смене проверки исчезает прежний диагноз. Механик видит просьбу повторить замер. Кнопка создания заявки и ссылки на ремонтные работы отсутствуют. |

Дополнительно второй посетитель с отдельной cookie проходит C1 по тому же учебному ТС и получает собственный номер заявки.

Успех завершается кодом 0 и выводом проверенных сценариев. Эмуляция проверяет мобильную вёрстку и сенсорные действия в Chromium. Для проверки конкретного телефона откройте адрес стенда в его браузере.
