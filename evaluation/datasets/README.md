# Вопросы заказчика для бенчмарка

[`customer_questions.jsonl`](customer_questions.jsonl) содержит 241 вход для бенчмарка. Из них 206 проверяют поиск и ответы по руководствам, 25 — основной сценарий агента, 8 — дополнительные функции, 2 — переформулирование с примерами поисковых запросов заказчика. Идентификаторы исходных кейсов сохранены.

В наборе четыре дословных вопроса и две дословные команды. Остальные входы сформулированы по требованиям, сценариям или материалам руководств. Два внутренних поисковых запроса из бизнес-процессов дословно сохранены в поле `reference_rewrite`.

## Формат

- `text` — запрос механика или подпись команды, которую можно передать агенту как текст.
- `context` — выбранный двигатель, пара ТС и сессии или предыдущие факты диалога. Для отрицательных тестов используются отсутствующие `S-UNKNOWN`, `UNKNOWN-VEHICLE` и существующая сессия другого ТС.
- `source` — документ, раздел и происхождение формулировки. `verbatim` обозначает дословную реплику или команду, `adapted` — вопрос, составленный по материалу.
- `focus`, `expected_tool`, `expected_behavior` — что проверяет сценарий. Для дополнительных функций ожидаемый инструмент задаёт цель проверки, включая ещё не реализованные вызовы.
- `split` и `group` — 170 примеров для разработки и 71 отложенный. Варианты одного сценария входят в одну группу. Например, `Q008`, `Q009` и `Q241` относятся к тепловым зазорам.
- `expected_evidence` — физические страницы PDF, считая с 1. `scope=passage` указывает страницы с опорным материалом, `scope=module` — диапазон ремонтного модуля, `scope=context` — справку для объяснения границ ответа. В вопросе о расхождении между документами нужны оба источника.
- `expected_answer` — эталонный ответ для каждого из 206 RAG-кейсов. Оценивайте смысл, числа, единицы, необходимый порядок действий и условия применимости. Дословное совпадение с формулировкой эталона не требуется.
- `answer_outcome` — ожидаемый тип ответа. `answer` используется в 196 кейсах, `partially_supported` в 4, `abstain` в 3, `conflicting_sources` в 3. При частичном ответе нужно сообщить подтверждённую часть и назвать недостающие данные. При расхождении нужно привести обе формулировки со ссылками, отметить различие и предложить уточнить применимость у специалиста или производителя для конкретной модификации.

## Использование

Для текстового прогона передавайте агенту `text` и нужные поля `context`. Для теста уточнения восстановите предыдущий ход из `prior_facts`. Для диагностических сценариев используйте запись поставленного Mock ML по паре ТС и сессии. Строки с `input_mode=ticket_confirmation` описывают отдельный вызов подтверждения. Поля источника и ожиданий нужны оценщику.

Для оценки попадания в источник используйте 202 кейса со ссылкой `passage` или `module`. Для многостраничной процедуры измеряйте и попадание в модуль, и охват нужных частей. Кейсы со ссылками только `context` или без страниц используйте для оценки обоснованного воздержания и применимости источников. Среди RAG-кейсов 143 примера для разработки и 63 отложенных.

Для ЯМЗ-236М2 кейсы `Q008` и `Q241` проверяют расхождение в условиях регулировки. Физическая стр. 31 РЭ указывает «менее чем через 15 минут», физические стр. 269 и 276 РК — «не ранее чем через 15 минут» в описанных там процедурах. Для демонстрации согласовано регулировать на холодном двигателе. Пятнадцать минут после остановки сами по себе не подтверждают, что двигатель остыл.

## Упрощённый формат retrieval

`python -m evaluation.retrieval` читает `customer_questions.jsonl` напрямую (формат определяется по полю `text`), режимы запроса и сопоставление документов описаны в [docs/retrieval.md](../../docs/retrieval.md). Для быстрых проверок он также читает отдельный JSONL, по строке на вопрос: `id`, `engine_model` (как в `vehicles.json`), `question`, `relevant` — эталонные физические страницы `[{"document_id", "pdf_page"}]` с `document_id` из каталога ingestion. Пустой `relevant` означает вопрос без ответа в корпусе. `split`: `dev` или `holdout`. Пример — [`retrieval.example.jsonl`](retrieval.example.jsonl), страницы в нём нужно сверить с PDF.
