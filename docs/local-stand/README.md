# Локальная проверка «Цифрового механика» с данными заказчика

Этот сценарий поднимает React и Go, Python-агента, поиск по шести руководствам, распознавание речи и обе штатные заглушки заказчика. В браузере вы проходите тот же путь от выбора замера до заявки, что и на HTTPS-стенде. Локальные диалоги, заявки и индексы хранятся отдельно. Команды ниже рассчитаны на Bash или Zsh и выполняются из корня репозитория.

В Codex этот же сценарий запускается запросом «Используй $local-stand-testing, подними локальный стенд и пройди C1–C3». Если чего-то не хватает, скилл попросит путь к конкретному файлу или подскажет, какую переменную заполнить.

## 1. Подготовьте комплект

Понадобятся Git, Docker с Compose 2.24.4+, запущенный Docker Engine, Python 3 и комплект заказчика, полученный отдельно. Первый запуск скачивает образы, зависимости и веса Whisper. На macOS запустите Docker Desktop и разрешите ему читать каталоги с данными. Проверьте доступ командой `docker info`.

| Переменная | Что должно лежать по этому пути на вашем компьютере |
|---|---|
| `FLEET_DIR` | Шесть оригинальных PDF непосредственно в каталоге и один исходный архив `neurodvs_hackathon_mock_*.zip`. Имена и SHA-256 PDF перечислены в [манифесте](../../ml/ingestion/manifest.json). |
| `MOCK_DIR` | Распакованный комплект из этого ZIP. Непосредственно внутри находятся `mock_ml/app.py`, `mock_toir/app.py` и `data/vehicles.json`. |

Укажите абсолютные пути, сохраняя кавычки для имён с пробелами. Если архив уже распакован, достаточно задать обе переменные. Для первого извлечения в новый каталог подойдёт такой пример:

```bash
export FLEET_DIR="/абсолютный/путь/к/комплекту"
unpack_dir="$(mktemp -d)"
unzip -q "$FLEET_DIR/neurodvs_hackathon_mock_2026-11-16.zip" -d "$unpack_dir"
export MOCK_DIR="$unpack_dir/neurodvs_hackathon_mock_2026-11-16"
python3 .agents/skills/local-stand-testing/scripts/check_inputs.py \
  --fleet-dir "$FLEET_DIR" --mock-dir "$MOCK_DIR"
```

Для комплекта от 16.11.2026 ожидается `PDF: 6, ТС: 50, замеры: 195`. Для регулярной работы распакуйте ZIP в постоянный личный каталог. Если проверка сообщила о несовпадении SHA-256, запросите у владельца указанную редакцию PDF. Исходный ZIP нужен агенту для справочника машин, распакованная копия — контейнерам моков для запуска их кода. Материалы Яндекс Диска, извлечённый текст, индексы и файлы заявок храните вне checkout.

## 2. Поднимите стенд своей ветки

Из checkout **тестируемой фичи** запустите помощник. Нужны Docker Engine с Compose 2.24.4+ и Python 3.9+. Браузер для E2E, Go, Node и Whisper собираются или устанавливаются в контейнеры. Команда использует продовые Dockerfile и оба Compose-файла проекта; локальный слой задаёт изоляцию и сертификат Caddy.

```bash
test -f .env || (umask 077 && cp .env.example .env)
stand() { python3 .agents/skills/local-stand-testing/scripts/stand.py "$@"; }
stand up
```

Для повторного запуска сохраните абсолютные `FLEET_DIR` и `MOCK_DIR` в приватном `.env` этой копии. Профиль по умолчанию использует локальный планировщик, генерацию A и гибридный поиск с `retrieval-web-hybrid.yaml`. Порог уверенности 70%, при помехах предлагается повторный замер. DeepSeek Flash генерирует ответ, GLM Flash проверяет его. Укажите `LLM_API_KEY` и получите разрешение на передачу вопросов и текста руководств OpenRouter. Команда `stand up --baseline` выбирает локальный BM25 и проверенные выдержки.

При первом запуске создаются приватная сеть, SQLite и индексы в проектном томе, оба штатных мока, агент, Go с фронтом, speech и HTTPS-шлюз. Сценарий печатает URL вида `https://mech-…-dev.localhost:<порт>/`, логин и **путь** к файлу пароля. Docker назначает свободный порт. У каждого checkout своё имя образа агента/моков, тома состояния и Caddy, адрес и браузерная cookie. Образы базовых слоёв могут использовать общий кэш.

Caddy выпускает локальный сертификат. В тестовом Chromium доверие к локальному шлюзу настроено контекстом теста. Для ручной проверки сверяйте сертификат с CA из `build/local-stand/dev/ca.crt`; например, `curl --cacert build/local-stand/dev/ca.crt --user mechanic "$URL/health"` (подставьте выданный URL, пароль вводится по запросу). Для ручной диктовки используйте браузер, доверяющий этому локальному CA. Файлы доступа находятся под игнорируемым `build/`.

## 3. Запустите E2E прямо на поднятом стенде

```bash
stand status
stand e2e
```

Второй вызов поднимает только одноразовый Chromium в сети **этого** проекта. Он входит через Caddy с Basic Auth, проходит Go → Python → клиентские ML и ТОиР, проверяет черновик, печать, подтверждение и повтор, вопрос о перегоне и плохую запись. Заявка создаётся в локальном моке; после теста приложение продолжает работать, результаты можно смотреть вручную. Тест запускается с новой браузерной сессией. Если на этот замер уже оформляли заявку, он отдельно проверяет блокировку дубликата; для проверки первой квитанции выберите чистый слот.

Для сценария своей фичи положите Python-файл Playwright в `tests/` тестируемой ветки. В контейнере он видит это дерево в `/feature-tests`, приложение по `https://gateway` и переменные `STAND_USER`, `STAND_PASSWORD`. Образец настройки контекста — [smoke.py](../../tests/e2e/stand/smoke.py).

```bash
stand e2e --test my_feature.py
stand logs
stand down
```

`down` останавливает только свой Compose-проект. SQLite и индексы остаются в его томе. Штатный ТОиР держит свой список заявок в памяти процесса. Для чистого состояния без удаления старых данных используйте другой слот, например `stand up --baseline --instance print`, затем `stand e2e --instance print` и `stand down --instance print`. Для параллельного тестирования разных веток откройте каждую в отдельном git worktree и выполните те же команды там. После изменений кода повторите `stand up` с выбранным профилем для пересборки.

Если в старой feature-ветке помощник ещё отсутствует, используйте абсолютный путь к `stand.py` из checkout с этим скиллом. Рабочим каталогом оставьте корень feature-ветки. Код, Dockerfile, основные Compose-файлы и `.env` берутся оттуда; доступны ветки с Compose-стеком и сервисом речи. Для разных компьютеров нужны собственные пути к комплекту и свой локальный ключ.

## 4. Пройдите приёмку в браузере

| Сценарий | Действие и ожидаемый результат |
|---|---|
| C1, отклонение | Выберите ЯМЗ-236М2 → M333YK47 → S-0005, получите диагностику. Проверьте тип отклонения, риск и рекомендацию. Откройте источник на стр. 52 внутри сайта. Разверните блок выполненных проверок, если ответ содержит отчёт. |
| Черновик, печать, подтверждение | Во вкладке «Заявка» создайте черновик, смените приоритет и нажмите «Печать». В PDF должны попасть выбранный приоритет, только подтверждённые работы и страницы. Печать доступна до подтверждения. Для проверки отправки подтвердите один раз в локальном Mock ТОиР и проверьте номер заявки. |
| C2, вопрос о перегоне | После отклонения спросите «Можно ли своим ходом доехать до базы?». Проверьте, что разрешение эксплуатации имеет применимый источник или что агент сообщает об отсутствии оснований. |
| Норма и C3 | Для P456AT178 выберите сначала S-0001 (норма), затем S-0003 (сбой проверки). При сбое предлагается повторный замер, а создание заявки заблокировано. |
| Применимость нормативов | Для ЗМЗ-5234.10 спросите про момент затяжки крышек коренных подшипников. Откройте страницу из ответа и сверьте двигатель. Поиск и номера страниц проверяются и в автоматическом прогоне. |
| Диктовка | Разрешите микрофон на localhost, надиктуйте «Запусти диагностику двигателя» и остановите запись. Текст должен появиться в поле для правки. Отправка — отдельное действие. Для реального телефона нужен доступ по HTTPS с доверенным сертификатом; localhost телефона указывает на сам телефон. |

**Дополнительный нативный регрессионный тест.** Основной E2E для параллельной разработки — `stand e2e` из шага 3. При необходимости диагностики поиска можно отдельно выполнить `customer_smoke.py`. Он запускает собственные Go, Python и два штатных мока на свободных портах, использует временное хранилище и фиксирует профиль baseline. Этим удобно проверить повторное подтверждение после ручных опытов, даже если в вашем Compose уже создана заявка. Для этого отдельного теста на машине нужны Go 1.25+, Node.js 22, npm, Python 3.12 и браузер:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[api]' 'playwright>=1.50,<2'
.venv/bin/python -m playwright install chromium
npm --prefix app/frontend ci
npm --prefix app/frontend run build
mkdir -p build
(cd app/backend && go build -tags=nomsgpack -o ../../build/mechanic-web .)
RETRIEVAL_CONFIG_PATH="$PWD/configs/retrieval-web.yaml" \
  PYTHONPATH=. .venv/bin/python tests/e2e/customer_smoke.py \
  --backend build/mechanic-web --data-dir "$FLEET_DIR" --mock-dir "$MOCK_DIR"
```

Путь в `RETRIEVAL_CONFIG_PATH` указывает на файл хоста. Для установленного Google Chrome передайте `--channel chrome`. Чтобы повторно использовать индекс той же редакции и конфигурации, передайте `--index /путь/к/manuals.sqlite3`; рядом должен лежать `retrieval/`. По умолчанию тест построит собственный индекс. Тест проверяет C1–C3, историю заявок B1, внутренний аудит, поиск и открытие страницы PDF. [Описание браузерных тестов](../../tests/e2e/README.md)

## 5. Сверьте результат со стендом по SSH

Если доступ к серверу предоставлен, войдите по SSH и перейдите в каталог действующего релиза. На нашем стенде это `/opt/ai-mechanic/compose`. Команды ниже только читают состояние:

```bash
cd /opt/ai-mechanic/compose
readlink -f .
dc() { docker compose -p ai-mechanic -f compose.yaml -f compose.stand.yaml "$@"; }
dc ps -a
dc exec -T web mechanic health
dc exec -T agent python -c 'import httpx; r=httpx.get("http://web:8080/api/vehicles"); r.raise_for_status(); v=r.json()["vehicles"]; print(len(v), sum(len(x["sessions"]) for x in v))'
```

Последняя команда рассчитана на стандартный внутренний порт 8080. Для сравнения настроек выполните следующую команду сначала в серверной оболочке, для локального стенда сравните с профилем, выбранным в шаге 2:

```bash
dc exec -T agent python -c 'from ml.config import Settings; keys="planner_mode agent_architecture allow_external_evidence web_retrieval_mode retrieval_config_path min_diagnostic_confidence repeat_on_warning llm_model a_generator_model a_verifier_model answer_language".split(); print(Settings().model_dump(include=set(keys),mode="json"))'
```

Сравните релиз, активный профиль, конфиг поиска и каталог машин. В HTTPS-шлюзе ответ 401 без учётных данных ожидаем. Проверяйте браузерный вход отдельно от внутреннего healthcheck. Локальные логи доступны через `stand logs`. Вывод полного Compose-конфига и серверный .env могут содержать секреты.
