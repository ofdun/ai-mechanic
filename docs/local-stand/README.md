# Локальная проверка «Цифрового механика» с данными заказчика

Этот сценарий поднимает React и Go, Python-агента, поиск по шести руководствам, распознавание речи и обе штатные заглушки заказчика. В браузере вы проходите тот же путь от выбора замера до заявки, что и на HTTPS-стенде. Локальные диалоги, заявки и индексы хранятся отдельно. Команды ниже рассчитаны на Bash или Zsh и выполняются из корня репозитория.

В Codex этот же сценарий запускается запросом «Используй $local-stand-testing, подними локальный стенд и пройди C1–C3». Если чего-то не хватает, скилл попросит путь к конкретному файлу или подскажет, какую переменную заполнить.

## 1. Подготовьте комплект

Понадобятся Git, Docker с Compose 2.24+, запущенный Docker Engine, Python 3 и комплект заказчика, полученный отдельно. Первый запуск скачивает образы, зависимости и веса Whisper. На macOS запустите Docker Desktop и разрешите ему читать каталоги с данными. Проверьте доступ командой `docker info`.

| Переменная | Что должно лежать по этому пути на вашем компьютере |
|---|---|
| `FLEET_DIR` | Шесть оригинальных PDF непосредственно в каталоге и один исходный архив `neurodvs_hackathon_mock_*.zip`. Имена и SHA-256 PDF перечислены в [манифесте](../../ml/ingestion/manifest.json). |
| `MOCK_DIR` | Распакованный комплект из этого ZIP. Непосредственно внутри находятся `mock_ml/app.py`, `mock_toir/app.py` и `data/vehicles.json`. |

Укажите абсолютные пути, сохраняя кавычки для имён с пробелами. Если архив уже распакован, достаточно задать обе переменные. Для первого извлечения в новый каталог подойдёт такой пример:

```bash
export FLEET_DIR="/абсолютный/путь/к/комплекту"
unpack_dir="$(mktemp -d)"
unzip -q "$FLEET_DIR/neurodvs_hackathon_mock_2026-11-16.zip" -d "$unpack_dir"
export MOCK_DIR="$unpack_dir/neurodvs_hackathon_mock_2026-11-16"
python3 .agents/skills/local-stand-testing/scripts/check_inputs.py \
  --fleet-dir "$FLEET_DIR" --mock-dir "$MOCK_DIR"
```

Для комплекта от 16.11.2026 ожидается `PDF: 6, ТС: 50, замеры: 195`. Для регулярной работы распакуйте ZIP в постоянный личный каталог. Если проверка сообщила о несовпадении SHA-256, запросите у владельца указанную редакцию PDF. Исходный ZIP нужен агенту для справочника машин, распакованная копия — контейнерам моков для запуска их кода. Материалы Яндекс Диска, извлечённый текст, индексы и файлы заявок храните вне checkout.

## 2. Настройте локальный профиль

```bash
test -f .env || (umask 077 && cp .env.example .env)
```

Впишите в локальный `.env` фактические `FLEET_DIR` и `MOCK_DIR`, чтобы настройки пережили закрытие терминала. Экспортированные переменные оболочки имеют приоритет над одноимёнными строками файла. Пример общей части:

```dotenv
COMPOSE_PROFILES=mocks
WEB_PORT=8080
ML_API_URL=http://ml:8001
MAINTENANCE_API_URL=http://maintenance:8002
PLANNER_MODE=local
WEB_RETRIEVAL_MODE=team
RETRIEVAL_CONFIG_PATH=/app/configs/retrieval-web.yaml
MIN_DIAGNOSTIC_CONFIDENCE=0.70
REPEAT_ON_WARNING=true
```

Оставьте `STATE_DIR` по умолчанию: Compose создаст том проекта. Для входа по localhost учётные данные шлюза не нужны. Имена `ml` и `maintenance` разрешаются внутри сети Docker. Если меняете провайдера, задайте базовый URL через соответствующую переменную. Клиент сам добавляет путь операции.

**Приёмка без расходов.** Для сценариев C1–C3, проверки PDF, печати и защиты заявки оставьте `AGENT_ARCHITECTURE=baseline` и `ALLOW_EXTERNAL_EVIDENCE=false`. Работают штатные моки, локальный поиск, проверенные выдержки и Whisper. Формулировки генеративных ответов и качество перевода проверяйте отдельно.

**Ответы как на стенде.** На проверенном релизе сервер использовал профиль A со следующими настройками:

```dotenv
AGENT_ARCHITECTURE=a
ALLOW_EXTERNAL_EVIDENCE=true
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=z-ai/glm-5.3-flash
A_GENERATOR_MODEL=deepseek/deepseek-v4.1-flash
A_VERIFIER_MODEL=z-ai/glm-5.3-flash
ANSWER_LANGUAGE=ru
```

Добавьте свой действующий `LLM_API_KEY` в локальный `.env`. Этот профиль может передать OpenRouter вопрос, фрагменты руководств и контекст замера. Используйте его с разрешением владельца данных. Для одной проверки достаточно одного вопроса, требующего генерации; ответ из проверенного каталога сам по себе не доказывает, что модель вызвана. Версия модели, выбор источников и недоступность провайдера могут влиять на результат.

## 3. Поднимите Compose и проверьте вход через Go

Выполняйте команды в одном терминале. Функция `dc` явно выбирает локальный Compose-файл и отдельное имя проекта. Если порт занят, заранее смените `WEB_PORT` в `.env`; адрес для проверок ниже измените соответственно.

```bash
dc() { docker compose -p mechanic-local -f compose.yaml --profile mocks "$@"; }
dc config --quiet
dc build agent web speech
dc up -d --wait --wait-timeout 600
dc ps -a
dc logs --tail=20 index
```

У `index` нормальное конечное состояние — `Exited (0)`; в логе ожидается 1743 физические страницы. У `agent` и `web` ожидается `healthy`, у `ml`, `maintenance` и `speech` — работающий контейнер. Ранний старт контейнера речи ещё не подтверждает готовность модели.

```bash
base=http://127.0.0.1:8080
curl -fsS "$base/health"
curl -fsS "$base/api/vehicles" | python3 -c 'import json,sys; v=json.load(sys.stdin)["vehicles"]; print(len(v), sum(len(x["sessions"]) for x in v))'
```

Ожидаются статус `ok` и числа `50 195`. Откройте тот же адрес в браузере. После изменения профиля выполните `dc up -d --no-deps --force-recreate --wait agent`. После изменения кода пересоберите затронутые образы. При замене руководств или настроек разбиения страниц остановите локальные `agent web`, выполните `dc run --rm index` и запустите `dc up -d --wait`.

## 4. Пройдите приёмку в браузере

| Сценарий | Действие и ожидаемый результат |
|---|---|
| C1, отклонение | Выберите ЯМЗ-236М2 → M333YK47 → S-0005, получите диагностику. Проверьте тип отклонения, риск и рекомендацию. Откройте источник на стр. 52 внутри сайта. Разверните блок выполненных проверок, если ответ содержит отчёт. |
| Черновик, печать, подтверждение | Во вкладке «Заявка» создайте черновик, смените приоритет и нажмите «Печать». В PDF должны попасть выбранный приоритет, только подтверждённые работы и страницы. Печать доступна до подтверждения. Для проверки отправки подтвердите один раз в локальном Mock ТОиР и проверьте номер заявки. |
| C2, вопрос о перегоне | После отклонения спросите «Можно ли своим ходом доехать до базы?». Проверьте, что разрешение эксплуатации имеет применимый источник или что агент сообщает об отсутствии оснований. |
| Норма и C3 | Для P456AT178 выберите сначала S-0001 (норма), затем S-0003 (сбой проверки). При сбое предлагается повторный замер, а создание заявки заблокировано. |
| Применимость нормативов | Для ЗМЗ-5234.10 спросите про момент затяжки крышек коренных подшипников. Откройте страницу из ответа и сверьте двигатель. Поиск и номера страниц проверяются и в автоматическом прогоне. |
| Диктовка | Разрешите микрофон на localhost, надиктуйте «Запусти диагностику двигателя» и остановите запись. Текст должен появиться в поле для правки. Отправка — отдельное действие. Для реального телефона нужен доступ по HTTPS с доверенным сертификатом; localhost телефона указывает на сам телефон. |

**Автопрогон с полным комплектом.** Он запускает собственные Go, Python и два штатных мока на свободных портах, использует временное хранилище и фиксирует профиль baseline. Этим удобно проверить повторное подтверждение после ручных опытов, даже если в вашем Compose уже создана заявка. Для этого отдельного теста на машине нужны Go 1.25+, Node.js 22, npm, Python 3.12 и браузер:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[api]' 'playwright>=1.50,<2'
.venv/bin/python -m playwright install chromium
npm --prefix app/frontend ci
npm --prefix app/frontend run build
mkdir -p build
(cd app/backend && go build -tags=nomsgpack -o ../../build/mechanic-web .)
RETRIEVAL_CONFIG_PATH="$PWD/configs/retrieval-web.yaml" \
  PYTHONPATH=. .venv/bin/python tests/e2e/customer_smoke.py \
  --backend build/mechanic-web --data-dir "$FLEET_DIR" --mock-dir "$MOCK_DIR"
```

Путь в `RETRIEVAL_CONFIG_PATH` здесь указывает на файл хоста: автотест запускает Python вне контейнера. Для установленного Google Chrome передайте `--channel chrome`. Чтобы повторно использовать проверенный индекс той же редакции и конфигурации, передайте `--index /путь/к/manuals.sqlite3`; рядом должен лежать `retrieval/`. Без этого ключа тест построит собственный индекс. Успешный прогон выводит `PASS: 50 vehicles / 195 sessions, C1–C3, confirmed ticket and replay, team search and cited PDF pages.` Подробности — в [описании браузерных тестов](../../tests/e2e/README.md).

## 5. Сверьте результат со стендом по SSH

Если доступ к серверу предоставлен, войдите по SSH и перейдите в каталог действующего релиза. На нашем стенде это `/opt/ai-mechanic/compose`. Команды ниже только читают состояние:

```bash
cd /opt/ai-mechanic/compose
readlink -f .
dc() { docker compose -p ai-mechanic -f compose.yaml -f compose.stand.yaml "$@"; }
dc ps -a
dc exec -T web mechanic health
dc exec -T agent python -c 'import httpx; r=httpx.get("http://web:8080/api/vehicles"); r.raise_for_status(); v=r.json()["vehicles"]; print(len(v), sum(len(x["sessions"]) for x in v))'
```

Последняя команда рассчитана на стандартный внутренний порт 8080. Для сравнения настроек выполните следующую команду сначала в серверной оболочке, затем в локальной с локальной функцией `dc` из шага 3:

```bash
dc exec -T agent python -c 'from ml.config import Settings; keys="planner_mode agent_architecture allow_external_evidence web_retrieval_mode retrieval_config_path min_diagnostic_confidence repeat_on_warning llm_model a_generator_model a_verifier_model answer_language".split(); print(Settings().model_dump(include=set(keys),mode="json"))'
```

Сравните релиз, активный профиль, конфиг поиска и каталог машин. В HTTPS-шлюзе ответ 401 без учётных данных ожидаем. Проверяйте браузерный вход отдельно от внутреннего healthcheck. Для диагностики локального сбоя используйте `dc logs --tail=60 web agent`, для диктовки — `dc logs --tail=30 speech`. Полный вывод `docker compose config`, переменные контейнера и серверный `.env` могут содержать ключи.

Завершайте локальную работу командой `dc down` **в локальной оболочке**. Том с индексом и квитанциями сохранится. Штатный Mock ТОиР держит собственные заявки в памяти процесса: перезапуск мока не очищает историю отправки в приложении. Для повторяемого теста используйте изолированный автопрогон из шага 4.
